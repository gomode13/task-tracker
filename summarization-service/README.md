# Summarization Service

Сервис суммаризации для Task Tracker. Получает из Kafka заявки на дневной отчёт, отправляет содержимое задач в языковую модель GigaChat и возвращает готовый текст обратно в Kafka.

Сервис работает без HTTP-интерфейса: единственный способ общения с ним — сообщения Kafka.

## Как это работает

1. Планировщик Task Tracker в полночь собирает задачи каждого пользователя и кладёт заявку в топик `daily-report-requests`.
2. Сервис читает заявку, проверяет по своей базе, не обрабатывал ли он её раньше, и обращается к GigaChat.
3. Готовый текст уходит в топик `daily-report-responses`, а `request_id` заявки записывается в базу как обработанный.
4. Планировщик сопоставляет ответ с получателем по `request_id` и отправляет письмо.

Почта пользователя сервису не передаётся: он видит только заголовки задач и идентификатор заявки.

## Формат сообщений

Заявка, топик `daily-report-requests`:

```json
{
  "request_id": "c2b8f0f2-6b6a-4f0e-9f1e-2a1c9d3e4f5b",
  "completed_titles": ["Сдать отчёт за квартал"],
  "pending_titles": ["Записаться к стоматологу", "Купить корм коту"]
}
```

Ответ, топик `daily-report-responses`:

```json
{
  "request_id": "c2b8f0f2-6b6a-4f0e-9f1e-2a1c9d3e4f5b",
  "summary": "Вчера вы сдали квартальный отчёт — самое тяжёлое позади.",
  "error": null
}
```

Если обращение к модели не удалось, в `summary` приходит `null`, а в `error` — описание ошибки. Ответ отправляется в обоих случаях, чтобы планировщик не ждал впустую.

## Защита от повторной обработки

Каждый обработанный `request_id` записывается в таблицу `processed_requests` с уникальным ограничением. Если та же заявка придёт повторно, сервис её пропустит и обращаться к модели не станет.

## Технологии

Python 3.14, aiokafka, SQLAlchemy 2.0, Alembic, asyncpg, PostgreSQL, Pydantic v2, httpx, Poetry.

## Настройки

Скопируйте `.env.example` в `.env` и заполните значения.

| Переменная | Назначение |
| --- | --- |
| `KAFKA_HOST`, `KAFKA_PORT` | Адрес брокера Kafka |
| `POSTGRES_HOST`, `POSTGRES_PORT` | Адрес базы сервиса |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Доступ к базе |
| `GIGACHAT_AUTH_KEY` | Ключ авторизации из личного кабинета GigaChat |
| `GIGACHAT_CA_CERT_FILE` | Путь к сертификату Минцифры |

Сертификат «Российский доверенный корневой УЦ» скачивается с [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt) — нужен обычный вариант, не ГОСТ. Без него запрос к GigaChat не проходит проверку сертификата.

## Запуск

Зависимости:

```
poetry install
```

База поднимается вместе с остальной инфраструктурой Task Tracker:

```
docker compose up -d summarization-postgres kafka
```

Таблицы:

```
poetry run alembic upgrade head
```

Сам сервис:

```
poetry run python -m app.main
```

Сервис остаётся запущенным и ждёт заявки. Остановка — Ctrl+C.

## Структура

```
app/
    main.py            точка входа: запускает консьюмер
    config.py          настройки из .env
    logging_config.py  настройка логов
    schemas.py         модели сообщений — заявка и ответ
    service.py         обработка заявки: проверка дублей, поход в модель, отправка ответа
    models.py          таблица обработанных заявок
    database.py        подключение к базе
    kafka/
        consumer.py    чтение топика заявок
        producer.py    отправка в топик ответов
    llm/
        client.py      HTTP-клиент GigaChat: авторизация и генерация
        prompts.py     системный промпт
alembic/               миграции
```
