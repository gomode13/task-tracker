# Task Tracker

A task manager with user accounts, email notifications and AI-generated daily
summaries. Built as a learning project for the
[zhukovsd python backend roadmap](https://zhukovsd.github.io/python-backend-learning-course/projects/task-tracker/).

Live at [gomode-task-tracker.ru](https://gomode-task-tracker.ru).

## Features

- Registration and login with JWT in http-only cookies
- Task list with done / not done sections
- Welcome email on registration
- Daily report: every user gets an email summarizing the day, with the summary
  text generated by an LLM

## Stack

- **Backend** — FastAPI, SQLAlchemy (async), Alembic, PostgreSQL
- **Background work** — Celery with RabbitMQ as a broker, Redis for results
- **Messaging between services** — Kafka
- **Summarization** — a separate service talking to GigaChat over HTTP
- **Frontend** — static HTML/CSS/JS served by nginx
- **Infrastructure** — Docker Compose, GitHub Actions, Docker Hub, Caddy

## Services

| Service | Role |
| --- | --- |
| `backend` | REST API: users, sessions, tasks |
| `email-sender` | Celery worker, queue `celery` — sends emails over SMTP |
| `report-worker` | Celery worker, queue `reports` — builds the daily report |
| `scheduler` | Celery beat — triggers the daily report on schedule |
| `summarization-service` | Reads a Kafka topic, asks the LLM, writes the answer back |
| `frontend` | nginx: static files plus a proxy to the backend |
| `caddy` | Entry point on ports 80 and 443, terminates TLS |
| `postgres` | Main database |
| `summarization-postgres` | Deduplication store for the summarization service |
| `rabbitmq` | Celery broker |
| `redis` | Celery result backend |
| `kafka` | Transport between the backend and the summarization service |

`backend`, `email-sender`, `report-worker` and `scheduler` share one image and
differ only by the command they run.

### Daily report flow

`scheduler` fires the task → `report-worker` collects the user's tasks for the
day and publishes a request to Kafka → `summarization-service` asks the LLM and
publishes the answer → `report-worker` picks it up and hands the letter to
`email-sender`.

## Running locally

Requires Docker and Docker Compose.

```bash
git clone https://github.com/gomode13/task-tracker.git
cd task-tracker

cp .env.example .env
cp task-tracker-backend/.env.example task-tracker-backend/.env
cp summarization-service/.env.example summarization-service/.env
```

Fill in the three copied files, then:

```bash
docker compose up -d --build
```

The app is served at `http://localhost`. Migrations run automatically before the
backend starts.

To stop:

```bash
docker compose down
```

## Environment

Three env files, each documented by its `.env.example`:

- `.env` — credentials for the infrastructure containers
- `task-tracker-backend/.env` — database, broker, JWT, SMTP
- `summarization-service/.env` — Kafka, GigaChat, its own database

The defaults in the examples are meant for Docker Compose. To run a service
outside Docker, replace the container names with `localhost` and use the ports
published on the host.

Two notes on SMTP: the project uses [Resend](https://resend.com) and connects
over implicit TLS. Ports 465, 587 and 25 are blocked outbound by many hosting
providers, so the deployed configuration uses Resend's alternative port `2465`.

## CI/CD

`.github/workflows/docker-ci.yml` runs on every push to `main` and on pull
requests. A matrix builds all three images and, outside of pull requests,
pushes them to Docker Hub as `godmode13/task-tracker-backend`,
`godmode13/task-tracker-frontend` and `godmode13/summarization-service`. The tag
is derived from the branch name, so images built from `main` are tagged `main`.

Both Python images use multi-stage builds: dependencies are installed with
Poetry in a builder stage and only the resulting virtualenv is copied into the
final image.

## Deployment

`docker-compose.prod.yml` is the compose file used on the server. It pulls the
published images instead of building them, and puts Caddy in front of the
frontend so the site is served over HTTPS with certificates obtained
automatically from Let's Encrypt.

On the server, place `docker-compose.prod.yml` (as `docker-compose.yml`),
`Caddyfile` and the three env files in one directory, then run
`docker compose up -d`.
